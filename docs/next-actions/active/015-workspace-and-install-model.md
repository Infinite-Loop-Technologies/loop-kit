# Workspace And Install Model

## Outcome

Define the workspace, project, artifact, install, and configuration model that the rewritten Loop platform expects so units can be built, installed, configured, and invoked coherently.

- Project plan: [../../project-plans/active/003-loop-refactor.md](../../project-plans/active/003-loop-refactor.md)

## Next Actions

- Define what a workspace contains and what metadata it owns.
- Define the difference between installed units, local projects, local overrides, and provider bundles.
- Define how configuration is split between workspace-level state and machine-level state.
- Define how installs, updates, removals, and cache reuse should behave.

## Notes

- This should replace the current ambiguous `loop.json`-style expectations with a clearer product model.
