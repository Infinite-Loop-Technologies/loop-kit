# Markdown Backlinks

Use this skill to maintain generated `## Backlinks` sections for markdown content in the agent's current working directory.

## Workflow

1. Inspect the repo for markdown scope.
Default includes are `**/*.md`, `**/*.mdx`, and `**/*.markdown`. Default excludes are `.git/**` and `node_modules/**`.

2. Run the sync script in check mode first when you want to see what would change.

```powershell
tsx ~/.codex/skills/markdown-backlinks/scripts/sync-markdown-backlinks.ts --check
```

3. Add `--include` and `--exclude` as needed.
Repeat the flags to narrow or expand the scan.

```powershell
tsx ~/.codex/skills/markdown-backlinks/scripts/sync-markdown-backlinks.ts --check --include "docs/**/*.md" --exclude "docs/archive/**"
```

4. Write changes only after the scope looks correct.

```powershell
tsx ~/.codex/skills/markdown-backlinks/scripts/sync-markdown-backlinks.ts --write
```

## Rules

- Treat the entire `## Backlinks` section as generated output owned by the script.
- Ignore links found inside generated backlink sections when building incoming-link graphs. This prevents false reciprocal backlinks.
- Ignore fenced code blocks when scanning links so examples do not create backlinks.
- Keep autogenerated backlinks sorted by relative source path.
- Leave authored content outside the managed `## Backlinks` section untouched.
- Report broken local markdown links. In `--check` mode they should fail verification. In `--write` mode the script still syncs backlinks, then exits non-zero so the caller can fix the broken links.

## Script

The script lives at [scripts/sync-markdown-backlinks.ts](./scripts/sync-markdown-backlinks.ts).

Arguments:

- `--check`: verify whether backlink sections are current; exit non-zero when updates are needed.
- `--write`: rewrite backlink sections in place.
- `--cwd <path>`: scan a different root instead of the current working directory.
- `--include <glob>`: include only matching markdown paths. Repeat as needed.
- `--exclude <glob>`: exclude matching paths. Repeat as needed.

Use `tsx` directly when it is on `PATH`. If it is not, use `bunx tsx` or another local launcher that can run TypeScript files without rewriting the script.

## Validation

Run the regression test after substantial edits to the skill logic:

```powershell
node --import tsx --test ~/.codex/skills/markdown-backlinks/scripts/sync-markdown-backlinks.test.ts
```
